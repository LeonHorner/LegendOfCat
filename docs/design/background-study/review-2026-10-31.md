## Transformed course

Terrain and shore footing positions are now local, matching the collider hierarchy.
The existing damp-foot tint uses course-relative height so its bands remain
registered with the transformed shore/water grid; default placement is unchanged.
Camera/world coordinates are converted into the scenery's local frame for parallax
and absolute tile recycling. Distant layer travel factors are unchanged; a fixed
world anchor retains the same water UV across camera motion/recycling. Water still
uses world coordinates in its unchanged shader. Placing/scaling the course places
its water grid too; camera motion does not scroll that grid through the world.

The course camera derives bounds, look-ahead, fixed height and framing size from
the placed course root. Its attached corner artwork inherits the same uniform scale.
At the normal identity placement, positions/framing and artwork are unchanged.
Positive uniform scales and translations are covered; rotated/nonuniform courses
are outside this regression's contract. Movement constants and collision geometry
are unchanged; scaled placements do not introduce rescaled physics or new abilities.

The integration regression covers translated placements with scales 0.75 and 1.5:
all fourteen painted contact rows against collider tops/centres, all five shore
footings, real grounded contact, camera framing, distant parallax displacement,
water UV stability at a tile boundary, checkpoint retry/full restart, and visual
alignment after a further root transform. Existing tests cover the normal route's
thirteen jumps, four checkpoints, immediate takeoff, water animation and menu round trip.

## Mipmap decision

The import loop's unreachable historical-texture condition is replaced by an
explicit disabled setting. No importer setting on the nine active textures changes.
The selected art is front-facing in a fixed orthographic view. Grounded/suspended
paintings use alpha rejection at 0.95, including fine grass and hanging leaves.
Ordinary averaged alpha mipmaps can erode that coverage and alter landing contours;
coverage-aware generation and minified color/grayscale/motion review would be
needed before enabling them selectively.

Uncompressed full mip chains would also add approximately one third to texture
storage. This pass retains the reviewed crisp appearance and existing storage,
without claiming it is universally the fastest/best filter. Minification shimmer
remains a possible art-quality tradeoff. A selective mip experiment is deferred;
no measured Editor FPS gain or resolution change is claimed.

## Follow-up: recovery after runtime placement changes

The first transformed-placement test did not cover recovery after a second runtime
transform. A new real-course regression activates checkpoint two, translates and
scales the root, retries from pause, induces a fall, revisits an earlier marker,
activates a later checkpoint, changes placement again, retries and fully restarts.
It also checks fall recovery at the new starting point after clearing progression.
The second placement is below world Y=-7, and both transforms occur while paused.
The old implementation failed its first recovery-position assertion by about
47.35 world units.

MovementCourse now supplies course-local Start/Spawn coordinates to RunLifecycle
and converts the returned point through the current root only when respawning.
Checkpoint proximity is tested in the same local frame. RunLifecycle remains a
coordinate-agnostic session state; progression, pause, counters, clock and reset
events are unchanged. No transform framework or persistent format is introduced.
The controller's optional fall reference uses course-local Y<-7 for this course;
standalone controllers without that reference retain the original world-Y boundary.
This prevents a valid low-placed course from repeatedly retrying after recovery.
Translation and positive uniform scale are supported. Rotation, mirroring, zero
scale and nonuniform scaling are unsupported; movement/gravity constants remain
in world units, so scaling geometry is not automatic traversal retuning.

Current reproduction instructions use pinned Unity 6000.3.27f2. Remaining f1
mentions in PR documentation identify historical captures/validation, including
the explicitly historical Mika preview section, and are not current setup advice.

Local follow-up validation: all 155 Unity Editor behavioral tests passed on
6000.3.27f2, including the new red/green runtime-recovery regression and the
previous scenery, jump, checkpoint, camera, water and menu integration tests.
Final exact-head Windows/Linux validation is recorded in PR #54.

## Follow-up: runtime scenery object lifecycle

Decorative quads now use MeshFilter/MeshRenderer objects sharing one owned unit
quad mesh. They never create primitive colliders, including during the opening
frame. Bounds, UV mapping, transforms, material assignments, custom water mesh
and terrain geometry remain unchanged. The current shaders do not consume normals
or tangents, so the render-only quad supplies positions and UVs only.

Owned meshes, material instances, sprite and pixel texture use deferred Destroy
in Play Mode. Edit-mode preview cleanup uses DestroyImmediate because there is
no deferred destruction loop there. Imported Resources artwork and materials
are borrowed assets and are never destroyed by scenery cleanup.

The real menu/course round-trip test checks decoration immediately after each
opening, then tracks generated resource references across both close/reopen cycles.
It verifies their destruction after the deferred cleanup frames and survival of
the source assets, alongside the existing input, checkpoint and menu assertions.
This lifecycle correction makes no rendering-performance claim.

All 155 local Unity behavioral tests passed on 6000.3.27f2 after this change,
including the extended close/reopen regression and existing gameplay, transformed
recovery, parallax and water tests. The lifecycle choice follows
[Unity's DestroyImmediate guidance](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/object/destroyimmediate).
PR #54 records the final exact-head CI result for both platforms.
